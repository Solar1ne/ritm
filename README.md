# Ритм · в своём темпе

Актуальные материалы: [руководство по возможностям](docs/features.md), [подготовка релиза web/Telegram/iPhone](docs/product-v1-release.md), [проверки и исправления от 22.10.2026](docs/quality-audit-2026-10-22.md).

Новое: [календарь активности 30/90 дней и итоги прошлой недели](docs/product-research-2026-10-22.md), адаптированные по исследованию Habitify, Streaks и Gentler Streak.

Работающий веб-PoC ассистента привычек по презентации RAT–PoC: цель → недельный план → дневник → объяснимое предложение → принятие следующей недели → история. Тот же интерфейс адаптирован для Telegram Mini App.

| Компонент | Исходники |
| --- | --- |
| Go API, доменные правила, PostgreSQL-адаптер и Telegram-бот | [backend](backend/) |
| Веб-интерфейс и Telegram Mini App | [frontend](frontend/) |
| iPhone и Swift-пакет клиента | [mobile/ios](mobile/ios/) |
| SQL-схема, миграции Goose и тестовые данные схемы | [database](database/) |

Сайт и HTTP API обслуживаются на одном origin. Go встраивает статические файлы из `frontend/static` при сборке. Мобильный клиент обращается к API, а PostgreSQL доступен бэкенду. Модуль сервера лежит в `backend/go.mod`. Корневой `go.work` связывает его с пакетами SQL и статических файлов.

## Запустить сайт

Выполняйте команды из корня проекта, где лежат `Makefile` и `compose.yaml`. Для разработки на компьютере используйте локальный запуск. Для размещения с HTTPS можно использовать Docker Compose.

### Локальный запуск

Установите Go 1.25+, PostgreSQL 16, Python 3 и `make`. Node.js и npm нужны для проверок фронтенда. Go-сервер отдаёт веб-интерфейс и API по одному адресу.

Если у вас уже есть настроенный локальный кластер «Ритма» и приватный `.local/database.env`, переходите к командам запуска. На новом компьютере запустите PostgreSQL и откройте базу `postgres` командой `psql -d postgres`. Если для входа требуется отдельная роль администратора, укажите её через `-U`. Выполните:

```sql
CREATE ROLE rhythm_app LOGIN;
\password rhythm_app
CREATE DATABASE rhythm OWNER rhythm_app;
\q
```

Задайте `DATABASE_URL` в окружении или создайте каталог командой `mkdir -p .local` и запишите строку ниже в `.local/database.env`. Укажите свой пароль и порт. Если пароль содержит специальные символы URL, используйте процентное кодирование. Для файла установите права `chmod 600 .local/database.env`.

```dotenv
DATABASE_URL=postgres://rhythm_app:YOUR_PASSWORD@127.0.0.1:5432/rhythm?sslmode=disable
```

Этот пример подходит для PostgreSQL на той же машине. Для удалённой БД используйте `sslmode=verify-full` и доверенный CA. Перед обновлением существующей схемы создайте проверенную копию. [PostgreSQL и перенос данных](docs/postgresql.md) · [Резервное копирование](docs/database-backups.md).

```sh
make db-status
make db-migrate
python3 scripts/dev.py start
```

`db-status` показывает зарегистрированные версии. `db-migrate` применяет ожидающие миграции через Goose. Последняя команда запускает сайт на `127.0.0.1:8080`. Откройте сайт в браузере и проверьте API в другом терминале:

```sh
curl --fail --show-error http://127.0.0.1:8080/api/health
```

Ожидается HTTP 200 и `"storage":"postgresql"` в ответе. `Ctrl+C` останавливает веб-сервер. [Открыть локальный сайт](http://127.0.0.1:8080).

### Запуск через Docker Compose

Понадобятся Docker с Compose, домен, направленный на сервер, и доступные порты 80 и 443. При первом запуске создайте `.env` из `.env.example` командой `cp -n .env.example .env`. Заполните `RHYTHM_DOMAIN` доменом без `https://`. Задайте два разных пароля в `POSTGRES_ADMIN_PASSWORD` и `POSTGRES_PASSWORD`.

```sh
docker compose config --quiet
docker compose up --build -d
docker compose ps -a
docker compose logs --tail=40 migrate app
```

Сначала Compose ждёт готовности PostgreSQL. Затем `migrate` применяет схему и завершается с кодом `0`. После этого `app` запускает Go-сервер, а Caddy направляет HTTPS-запросы к нему. Проверьте `/api/health` на своём домене. Для остановки с сохранением томов используйте `docker compose down`. Данные PostgreSQL находятся в томе `rhythm-postgres`. [Compose](compose.yaml) · [Dockerfile](Dockerfile) · [Настройка размещения](docs/postgresql.md#docker-compose-для-нового-размещения).

## Команды Makefile

`Makefile` хранит короткие имена для команд проекта. Когда вы вводите `make <цель>`, `make` выполняет команды, записанные под этой целью.

| Команда | Что выполняет |
| --- | --- |
| `make run` или `make` | Запускает `go run ./backend/cmd/server` с переменными текущего окружения. Для чтения `.local/database.env` используйте `python3 scripts/dev.py start`. |
| `make db-status` | Показывает состояние миграций через `scripts/dev.py status`. |
| `make db-migrate` | Применяет ожидающие миграции Goose через `scripts/dev.py migrate`. |
| `make db-create NAME=add_example_index` | Создаёт шаблон SQL-миграции в `database/migrations/` с временным префиксом UTC. |
| `make test` | Запускает Go-тесты с `-race` и тесты фронтенда. Для интеграционных тестов PostgreSQL задайте `RHYTHM_TEST_DATABASE_URL` отдельной тестовой БД. |
| `make check` | Запускает `go vet` и проверку синтаксиса фронтенда. |
| `make rat` | Запускает сценарии проверки правил адаптации. |
| `make quest-7-check` | На временной PostgreSQL проверяет миграцию, восстановление и очистку копий. |
| `make qa-release` | Запускает полный набор проверок релиза, включая тесты на временной PostgreSQL и браузерные сценарии. |
| `make release OUTPUT=/tmp/rhythm-release-new` | Собирает пакет Linux amd64 в новый каталог. |

[Makefile](Makefile) · [Квест 7](quest_7.md) · [Сборка и проверка релиза](docs/release-operations.md).

## Что реализовано

- PostgreSQL: транзакции, блокировки строк, миграция схемы, безопасный перенос JSON и проверенное восстановление SQL-бэкапа.
- Нативный iPhone-проект: Сегодня, План, Дневник, вход, экспорт и удаление аккаунта; расширенные функции через HTTPS WebView. [Подготовка Xcode/signing и публикации](docs/ios-release.md).
- Telegram-бот с личными `/start`, `/help`, `/privacy` и кнопкой Mini App. [Настройка и отдельный runtime](docs/telegram-product.md).
- Web: установка на главный экран, явное состояние потери связи, встроенная помощь и заполнение коллекций. Дневник требует соединения; приватные данные не кэшируются Service Worker.
- Первый запуск с предпросмотром расписания и отдельное мобильное меню всех разделов.
- Адаптивные обзор, недельный календарь, дневник с исправлением/удалением, прогресс, настройки и лаборатория.
- [Упражнения и техника движения](docs/exercises-feature.md): 12 локальных схематичных демонстраций, поиск, фильтры, пошаговые подсказки и первичные источники; просмотр без изменения дневника.
- Постоянные аккаунты: регистрация по логину и паролю, повторный вход, однократный резервный код, смена пароля, активные сеансы, завершение остальных сеансов и серверный выход. Регистрация сохраняет гостевую историю после подтверждения; email не используется. [Отчёт и проверки](docs/accounts-release.md).
- Принятие и отмена следующей недели, переход понедельника, неизменяемые расписания и просмотр истории. Изменение профиля влияет на новые предложения.
- Импорт CSV/TCX с предпросмотром, проверкой всего файла, защитой от дублей и явным согласием на зачёт занятия.
- Настройки напоминаний, календарь ICS с VALARM, отдельное разрешение уведомлений при открытом приложении.
- Помощник по собственному плану и дневнику, экспорт v2 и восстановление в пустой профиль.
- Настоящий AI через DeepSeek Chat Completions или OpenAI Responses: вопрос по фактам, разбор 14 дней, черновик записи из свободной фразы. Предпросмотр контекста и согласие на каждый запрос; подтверждение записи отдельно. Без ключа AI явно недоступен, локальный помощник работает. [Подключение DeepSeek](docs/deepseek.md).
- Варианты занятий по времени, месту и ограничению прыжков: предпросмотр, выбор, отмена, история, экспорт и календарь; исходное расписание сохраняется.
- История HRV и состава тела: сопоставимые серии, графики 30/90 дней и всей истории, исправления/удаления, экспорт и восстановление.
- Питание: 18 рецептов, предпочтения и исключаемые ингредиенты, предпросмотр и сохранение недели, замена блюд, список продуктов.
- Метрики импортированных пробежек: фактическое время, известная дистанция и темп без подстановки нулей.
- Карточка занятия или отдыха на сегодня, кольцо выполнения недели, быстрые кнопки самочувствия и история сна/усталости за 7/30 дней с просмотром дня. [Референсы и правила расчёта](docs/design-references.md).
- Чистое Go-ядро, приоритет восстановления, независимые последние показатели сна/усталости, отсутствие накопительного пересчёта.
- Постоянное хранение, изоляция браузерных/Telegram-аккаунтов, optimistic revision, идемпотентность отметок, серверная валидация и честные ошибки сохранения.
- Telegram SDK: `ready`, `expand`, тема, safe areas, кнопка «Назад», haptics; серверный HMAC/freshness и привязка запросов к текущему аккаунту.
- Воспроизводимые unit/integration/race/RAT/HTTP/browser проверки, C4, ADR, USM и матрица трассируемости.

Это PoC, а не медицински проверенная программа тренировок. Питание реализовано как подбор обычных блюд, HRV/состав тела — как история измерений. Добавки, лечебные назначения и прямое подключение к API часов не реализованы. Импорт доступен через выбранный файл CSV/TCX. ICS не синхронизируется автоматически, браузерные уведомления требуют открытого приложения. Полноценный UX-тест/пилот, реальный AI smoke и запуск в Telegram не подменяются техническими fixtures. [Контракт расширения](docs/ai-product-contract.md).

## Проверить

```sh
go -C backend test ./...
go -C backend test -race ./...
go -C backend vet ./...
staticcheck ./backend/...                  # если установлен
npm test
npm run check
go run ./backend/cmd/rat
go run ./backend/cmd/rat -json > docs/evidence/full-product/rat.json
```

После запуска сервера в другом терминале:

```sh
go run ./backend/cmd/loadtest -url http://127.0.0.1:8080 -rps 10 -duration 30s -output docs/evidence/full-product/http-load.json
```

CLI использует собственные искусственные гостевые профили, проверяет содержимое ответа и удаляет свои данные. Не запускайте на чужих серверах. Локальные 30 секунд проверяют HTTP + настроенное хранилище. [Прогон PostgreSQL](docs/evidence/postgresql/http-load.json) не доказывает массовый вход, 5-минутный SLO или работу 10 тысяч пользователей.

Браузерные тесты требуют Chrome и уже установленный Playwright. Приложению Playwright не нужен.

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright RHYTHM_EVIDENCE_DIR=docs/evidence/full-product node scripts/browser-check.mjs
PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright node scripts/full-product-check.mjs
PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright node scripts/ai-product-check.mjs
```

Проверка аккаунтов: `node scripts/accounts-check.mjs` с тем же `PLAYWRIGHT_MODULE`, только на отдельном сервере `127.0.0.1:18081` и тестовом `DATA_DIR`. [Команды и результаты нового этапа](docs/accounts-release.md), [машинный итог](docs/evidence/accounts/checks.json).

Доказательства базового релиза: `docs/evidence/full-product/`. AI, варианты, измерения и питание: `docs/evidence/ai-product/`, [отчёт расширения](docs/ai-release.md). Ранние браузерные AI-ответы — явно помеченные fixtures; последующий [живой прогон DeepSeek](docs/deepseek.md) проверил все три AI-сценария отдельно. В ограниченной среде задайте writable caches: `GOCACHE=/tmp/rhythm-go-cache`, `STATICCHECK_CACHE=/tmp/rhythm-staticcheck-cache`.

## Настройки сервера

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ADDR` | `127.0.0.1:8080` | Адрес прослушивания; в контейнере `:8080` |
| `DATABASE_URL` | пусто | PostgreSQL DSN; remote требует sslmode=verify-full. Локальный dev.py читает приватный .local/database.env |
| `DATA_DIR` | `.data` | Legacy файловый режим до миграции, один процесс на каталог |
| `PUBLIC_URL` | пусто | Точный публичный origin, например `https://rhythm.example.org` |
| `SESSION_SECRET` | сохраняется в БД / legacy DATA_DIR | Ключ не менее 32 байт, влияет и на Telegram identity. Нельзя произвольно менять после переноса |
| `TELEGRAM_BOT_TOKEN` | пусто | Токен бота только на сервере; без него Telegram-вход возвращает503 |
| `TIME_ZONE` | `Europe/Moscow` | IANA timezone календаря; клиент получает его от сервера |
| `AI_PROVIDER` | авто | `deepseek` или `openai`; обязателен, если настроены оба ключа. Нет автоматической отправки другому провайдеру |
| `DEEPSEEK_API_KEY` | пусто | Серверный ключ DeepSeek, не помещать во frontend или чат |
| `DEEPSEEK_MODEL` | `deepseek-flash` | Модель DeepSeek Chat Completions с JSON output; thinking отключён |
| `OPENAI_API_KEY` | пусто | Серверный ключ OpenAI; используется только при выборе OpenAI |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Модель с поддержкой Responses и strict structured outputs |
| `AI_TIMEOUT_SECONDS` | DeepSeek 20, OpenAI 3 | Время одного вызова: 1–30 секунд, без автоматического повтора |
| `AI_HOURLY_LIMIT` | `60` | Общий предел попыток AI за час на процесс, 1–10000 |

Все аккаунты одного сервера используют один календарный часовой пояс. Его смену для существующего хранилища планируйте как миграцию: даты уже сохранённых занятий не перемещаются автоматически.

Для AI задайте ключ в окружении процесса или секретах размещения и перезапустите сервер. `python3 scripts/dev.py start` также читает `.local/integrations.env` с правами0600; значения окружения имеют приоритет, файл не исполняется как shell. `go run` не читает `.env` автоматически; Docker Compose подставляет значения из `.env` через `compose.yaml`. Ключ не передаётся браузеру. Проверьте статус на странице помощника и выполните один запрос с искусственными данными и явным согласием. Расходы относятся к API-аккаунту владельца; подписка на приложение не заменяет API-ключ. [Доступ и отказоустойчивость](docs/adr/005-optional-ai-and-session-variants.md).
