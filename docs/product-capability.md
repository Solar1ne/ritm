# Полный цикл Ритма

## Пользовательский результат

Человек создаёт личный план, отмечает занятия и самочувствие, видит причины адаптации, принимает следующую неделю и возвращается к сохранённой истории. Один сервер и один интерфейс работают в браузере и Telegram Mini App. Полнота проверяется по сценариям презентации; успешная техническая проверка не означает доказанную медицинскую эффективность или максимальную оценку жюри.

## Контракт готовности

| Возможность | Наблюдаемый результат | Существенные исключения |
|---|---|---|
| Профиль и план | Цель, опыт, дни и время формируют расписание | Изменение настроек не переписывает сохранённые недели |
| Дневник | Выполнение, пропуск, сон и усталость сохраняются и исправляются | Будущие даты запрещены; исправление фактов ограничено 90 днями, удаление доступно для всей истории |
| Адаптация | Причина связана с фактическими сигналами | Пороги демонстрационные; нагрузка не растёт от повторных запросов |
| Следующая неделя | Пользователь принимает конкретное предложение или отменяет до начала недели | Устаревшее предложение не принимается молча; понедельник использует сохранённый план |
| История | Снимки недель сохраняют исходную длительность и тип занятий | У старых данных неизвестные детали явно помечены, а не выдуманы |
| Импорт | CSV/TCX проходит предварительную проверку, затем атомарное сохранение | Только выбранный локальный файл; явное согласие на зачёт в расписании; повторы не дублируются |
| Напоминания | Пользователь выбирает время и скачивает календарь с напоминаниями | ICS не синхронизируется автоматически; разрешение браузера отдельно, уведомления только пока приложение открыто |
| Помощник | Локальные ответы по правилам, AI-вопрос, разбор 14 дней и черновик из фразы | Настоящий AI требует серверный ключ; отдельное согласие на запрос, факты видны, запись только после проверки человеком; без ключа честно недоступен |
| Вариант занятия | Время, место и ограничение прыжков → preview → выбранное занятие | Исходный снимок сохраняется; ограничения восстановления, явная отмена, revision; выполненные и прошлые занятия не меняются |
| Измерения | HRV/вес/доля жира: сопоставимые серии, графики, исправления и удаления | Только введённые значения; методы и приборы не смешиваются; нагрузка не меняется по ним |
| Питание | 18 блюд, фильтры, preview недели, атомарное подтверждение, замены, список покупок | План не означает употребление; фильтр не гарантирует отсутствие следов аллергенов; нет лечебного рациона |
| Перенос данных | Экспорт и восстановление в пустой профиль | Не доверять identity, sessionBinding и revision из файла; не заменять существующие данные |
| Мобильная работа | Все действия доступны с клавиатуры и на узком экране | Реальный Telegram-вход требует бот и публичный HTTPS; локальный предпросмотр явно обозначен |

## Инженерные границы и риски

- Домен `internal/rhythm` владеет инвариантами и атомарной последовательностью. HTTP преобразует импорт/календарь/ответы в независимые DTO. Ручной composition root сохраняется; новых сторонних зависимостей не требуется.
- Repository — существующая внешняя граница; файловый адаптер сериализует операции одного процесса, применяет revision и атомарную замену файла. Несколько процессов на одной директории не поддерживаются. Лимиты возвращают ошибку вместо скрытого удаления истории.
- I/O получает context, HTTP имеет timeout и ограничение тела. Импорт всего пакета валидируется до сохранения. Повтор идентичного файла идемпотентен; конфликт идентификатора отклоняет весь пакет.
- Данные копируются при пересечении границ владения. Снимки недель неизменяемы. Клиент привязан к проверенной сессии, операции защищены от смены аккаунта в соседней вкладке.
- Background worker / брокер / распределённые транзакции: N/A — календарь создаётся по запросу, внешние сообщения не отправляются. Таймер интерфейса имеет явное завершение при уходе со страницы.
- Наблюдаемость: технические ошибки без содержимого дневника, токенов и имён; видимые ошибки и сохранение черновика на клиенте.
- AI: 3 секунды, отсутствие автоматических повторов, ограниченные квоты и circuit после трёх ошибок; пять успешных согласованных запросов восстанавливают доступ. Модель не владеет нагрузкой и не пишет в дневник. [Подробный контракт](ai-product-contract.md), [ADR-05](adr/005-optional-ai-and-session-variants.md).
- Обратная совместимость: ленивое преобразование старых записей с обозначением неизвестных деталей. Экспорт имеет версию схемы.

## Верификация

### PostgreSQL и завершённый первый запуск

Реализовано 17.10.2026: PostgreSQL подключён к локальному сайту, старые дневники и ключ перенесены, SQL backup восстановлен; первый запуск и мобильное меню доработаны. [Результаты и оставшиеся ограничения](postgresql-release.md). PostgreSQL driver — обоснованная новая зависимость для реальной внешней границы. Домен и HTTP-контракты дневника сохраняются; composition root выбирает адаптер явно. Аккаунты, session digests и отзывы — отдельные таблицы с ограничениями и индексами; ограниченный дневник остаётся атомарным JSONB-агрегатом с отдельной revision/owner.

Инварианты: одна успешная запись на исходную revision; потерянный ответ не дублирует факт; регистрация и смена владельца атомарны; старый guest не читает присоединённый дневник. DB row locks действуют между процессами, pool имеет владельца и Close при shutdown. Порядок блокировок — auth transaction lock, затем diary row; обычная запись дневника не берёт auth lock. Контекст, statement/lock timeouts и redaction DSN обязательны. Автоматический повтор произвольного callback запрещён.

Перенос: отдельная проверенная JSON-копия, отдельная data migration в пустую БД, общая транзакция, повтор по fingerprint безопасен; секрет сохраняется. После cutover файловый режим блокируется marker, отказ PostgreSQL не переключает историю обратно. Схема версионируется и проверяет checksum; миграции forward-only, destructive down отсутствует намеренно. Брокер, distributed transactions, billing: N/A — новых внешних эффектов нет.

Проверки: реальный PostgreSQL; конкуренция двух pools, claim/write и recovery, cancel/rollback, migration repeat/drift, полный read-back переноса и повторный вход после рестарта; `go test -race ./...`, `go vet ./...`, `staticcheck ./...`, frontend unit/browser и HTTP smoke. UX: понятный первый шаг, личный пустой профиль без выдуманной статистики, отдельная мобильная навигация с доступом к AI/питанию/измерениям. Публичный деплой и внешние credentials остаются отдельными проверками.

### Расширение: постоянный аккаунт

Контракт реализации: логин (3–32 латинских символа, цифры, точка, дефис, подчёркивание) и пароль-фраза (15–128 символов); регистрация явно сохраняет текущий гостевой дневник. Повторный вход возвращает тот же профиль в другом браузере. Одноразовый резервный код восстанавливает доступ без почтового провайдера; новый код заменяет прежний. Выход отзывает серверную сессию, смена пароля отзывает все старые сеансы. Telegram остаётся отдельной идентичностью; скрытого объединения нет.

Граница зависимостей: `accounts` владеет учётными данными и последовательностью входа, интерфейсом репозитория; `postgresstore` (и legacy `filestore`) — атомарной записью и проверкой версии при присоединении гостя; HTTP — cookies, Origin, лимитами запросов и DTO. Composition root передаёт зависимости явно. Данные аккаунта не входят в экспорт дневника. Пароли обрабатываются стандартным PBKDF2-HMAC-SHA256 с 600000 итераций и случайной солью; токены/резервный код сохраняются только как хеши. Само ядро аккаунтов использует stdlib; PostgreSQL adapter использует pgx.

Риски: устаревшая гостевая cookie после регистрации, запрос в полёте при смене владельца, повторное использование отозванного токена, гонки регистрации/сброса, перебор и дорогой KDF, потерянный ответ с резервным кодом. Проверка владения выполняется также под storage lock, история не копируется между несколькими файлами. KDF выполняется вне storage lock; число параллельных вычислений и попыток ограничено. Смена ключа/пароля подтверждается сравнением актуальных credentials внутри транзакции. Потерянный код можно заменить после входа с паролем. Контексты проходят через I/O, ошибки хранения не становятся успешным входом. Фоновые goroutine, email-рассылки, биллинг и распределённые транзакции: N/A — в этом расширении отсутствуют.

Приёмка: unit/integration/race на регистрацию, повторный вход, восстановление, отзыв, изоляцию и отказ хранилища; браузерный цикл с двумя независимыми сессиями, гостевой историей, ошибками формы и мобильным экраном. [Реализация и результаты](accounts-release.md). Публичный HTTPS, настоящие AI/Telegram и пользовательские исследования остаются отдельными внешними проверками.

`GOCACHE=/tmp/rhythm-go-cache go test -race ./...`, `go vet ./...`, `staticcheck ./...` при наличии; `npm test`, `npm run check`; браузерная проверка профиля, фактов, принятия/отмены плана, истории, импорта, экспорта/восстановления, доступности и мобильных размеров. RAT и нагрузочные измерения повторяются на текущем коде; доказательства новых проверок сохраняются отдельно от предыдущего этапа.

Живые интервью, экспертная проверка порогов и запуск через настоящего Telegram-бота нельзя заменить синтетическими тестами. Сценарии и материалы для защиты должны разделять выполненную проверку и ещё необходимые внешние подтверждения.
