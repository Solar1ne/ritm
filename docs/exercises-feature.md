# Каталог упражнений и техника движения

Каталог находится в web-интерфейсе по маршруту `#exercises`. Он помогает разобрать базовое движение: посмотреть схему, прочитать последовательность, подсказки, частые ошибки и более простой вариант. Личный тренировочный план для просмотра не требуется.

## Как открыть и пользоваться

- На компьютере выберите **«Упражнения»** в боковой навигации.
- В **«Плане недели»** нажмите **«Техника упражнений»**.
- На телефоне откройте **«Ещё» → «Упражнения»**.
- В **«Настройках и данных»** найдите **«Техника упражнений» → «Смотреть»**.

Поле **«Найти упражнение»** ищет по названию и русским/английским синонимам. Регистр и различие `е`/`ё` не влияют на результат. Фильтры **«Группа мышц»** и **«Инвентарь»** работают одновременно с поиском. Счётчик показывает число совпадений, **«Сбросить»** возвращает полный список. Если совпадений нет, можно изменить запрос или сбросить фильтры. При вводе фокус остаётся в поле поиска.

В карточке нажмите **«Смотреть технику»**. Откроется диалог со схемой движения, шагами, подсказками, частыми ошибками, облегчением и ссылками на первичные источники. Его можно закрыть кнопкой или Escape.

## Демонстрации

В каталоге 12 движений: приседание, выпад назад, ягодичный мост, отжимание от пола, отжимание от стены, планка на предплечьях, рука и нога на четвереньках, мёртвый жук, подъём на носки, тяга гантели в наклоне, сгибание рук с гантелями и наклон от таза.

Демонстрации — оригинальные локальные SVG-схемы основных фаз, а не видеозаписи тренера. Чужие фото, видео и встроенные проигрыватели не загружаются. Схема условна: она не проверяет исполнение пользователя и не задаёт индивидуальную амплитуду. Двигайтесь плавно; при боли остановитесь. Обоснование текстов и границы интерпретации приведены в [источниках каталога](exercise-sources.md).

Подвижные схемы открываются **на паузе**. **«Воспроизвести»** запускает движение, **«Пауза»** останавливает его. Стрелки переключают соседние ключевые положения, включая промежуточный шаг выпада; **«Сначала»** возвращает исходное. Ползунок позволяет разобрать любое промежуточное положение. У односторонних упражнений указана необходимость сменить сторону. Планка показана как статическое удержание.

Если в системе включено уменьшение движения (`prefers-reduced-motion`), автоматическое воспроизведение недоступно, ручные переключатели и ползунок работают. Воспроизведение останавливается при скрытии страницы. Закрытие или замена диалога, переход в другой раздел и сброс состояния освобождают обработчики и запланированный кадр анимации.

## Поверхности и границы

Каталог входит в общий web-интерфейс, включая Telegram Mini App. На iPhone он доступен через существующий **расширенный режим** сайта в WKWebView. Отдельный нативный каталог и новые Swift-экраны в эту фичу не входят. Проверки в Chrome с мобильным viewport не заменяют запуск на физическом iPhone или внутри реального Telegram-клиента.

Просмотр, поиск, фильтры и управление схемой работают только на чтение: они не отмечают тренировку, не добавляют упражнение в расписание и не меняют дневник. Данные каталога и координаты схем находятся в статических JavaScript-модулях; новые API, изменения Go-кода, схемы БД и миграции для каталога не требуются. Общая загрузка приложения и обновление состояния сохраняют существующий сетевой контракт; автономная работа каталога не заявлена.

Ссылки на источники допускают HTTPS без учётных данных в адресе и открываются с `noopener noreferrer`. Названия, тексты и адреса экранируются перед включением в HTML. Подходы, повторения и персональная нагрузка не назначаются. Каталог остаётся справочником техники.

## Инженерные решения и риски

| Область | Решение и граница |
| --- | --- |
| Зависимости и composition root | Статические данные, демонстрация и контроллер каталога разделены по ответственности. `app.js` явно передаёт существующие функции диалога. Новых зависимостей нет. |
| Go, API, БД, транзакции, идемпотентность | N/A — каталог не вводит серверных операций и не сохраняет записи. Публичные контракты и миграции не меняются. Go-сборка повторяется, поскольку web-ресурсы встроены в бинарный файл. |
| Конкурентность и lifecycle | Один владелец анимации на диалог; отмена кадра и удаление обработчиков при закрытии/замене/сбросе. Скрытие страницы и включение reduced motion ставят показ на паузу. Отложенное событие закрытия старого диалога не должно освобождать новый. |
| Владение данными | Каталог глубоко заморожен; координаты и список фаз возвращаются отдельными массивами. Поиск не изменяет исходные данные. |
| Ошибки и безопасность | Неизвестный ID не открывает карточку; некорректные ссылки отбрасываются. Нет скрытых запросов к AI или внешним медиасерверам. Источники открываются только по действию пользователя. |
| Производительность и совместимость | Фильтрация 12 записей локальная; обновляются только результаты и счётчик, сохраняя поле и каретку. Движение запускается явно, SVG рисуется только для открытой демонстрации. Совместимость остальных разделов проверяется общей browser-регрессией. |
| Observability | Браузерный отчёт фиксирует ошибки страницы, нежелательные записи и внешние медиазапросы на искусственном профиле. Новый сбор персональных данных не добавлен. |
| Точность показа | Схема не передаёт все детали объёмной техники. Для текста приведены первичные источники; все основные положения просмотрены отдельно от структурных тестов. |

## Как проверить

Из корня проекта запустите целевые тесты данных, фильтров, диалогов и управления демонстрациями:

```sh
node --test web/tests/exercises-data.test.js web/tests/exercise-demo.test.js web/tests/exercises.test.js
npm test
npm run check
```

Тесты охватывают структуру 12 упражнений, принадлежность тегов, неизменяемость данных, буквальный поиск и пересечение фильтров, экранирование и безопасные ссылки, сохранение элементов формы, отсутствие автоматического запуска, ручное управление, уменьшение движения и очистку ресурсов. Структурные тесты не подтверждают медицинскую корректность схем: их сопоставляют с описаниями и первичными источниками при содержательном просмотре.

Для browser-проверки нужен уже установленный Playwright, Chrome и запущенный **отдельный локальный Go/PostgreSQL-сервер с одноразовыми тестовыми данными**. Используйте новую папку результатов:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright \
RHYTHM_URL=http://127.0.0.1:18081 \
RHYTHM_EVIDENCE_DIR=/tmp/rhythm-exercises-browser-new \
node scripts/exercises-check.mjs
```

Общий изолированный прогон сам поднимает тестовое окружение и запускает подключённые проверки, включая каталог:

```sh
python3 scripts/qa.py --evidence-dir /tmp/rhythm-exercises-qa-new
```

Для регрессии Go-сборки используются `go test ./...`, `go test -race ./...`, `go vet ./...` и `staticcheck ./...` при наличии инструмента. Фактический результат конкретного прогона определяется его журналом и файлами в выбранной папке; эти команды сами по себе не являются заявлением об успешном QA, деплое или проверке устройств.

## Результат проверки 22 октября 2026

Общий изолированный QA завершился успешно: `go test -race -count=1 ./...` с реальной временной PostgreSQL 16, `go vet ./...`, `staticcheck ./...`, 136 Node-тестов (27 новых целевых), 26 Python-тестов, проверка синтаксиса и все 10 browser suites. `gofmt -l` не нашёл неформатированных Go-файлов. Go/SQL-исходники относительно предыдущего релиза не менялись. Временные сервер и база остановлены после прогона.

Браузерная приёмка проверила все 12 карточек и ключевые фазы, поиск и пересечение фильтров, фокус, экраны 320–1440 px, светлую/тёмную тему, reduced motion, явное воспроизведение/паузу и освобождение кадров при Escape/замене диалога. Дневник до и после просмотра совпал; записывающих запросов, внешних медиазагрузок и ошибок страницы не было. Основные положения всех схем также просмотрены вручную. Независимое ревью завершено без оставшихся замечаний.
