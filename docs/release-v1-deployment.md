# Установка подготовленного релиза

22.10.2026 владелец выбрал подготовку пакета: доступ к VPS будет предоставлен позже. Этот документ не подтверждает обновление работающего сервера. Историческая конфигурация: [VPS от 17.10](vps-deployment.md).

## Артефакты

- `dist/ritm-20261022-linux-amd64/`: `rhythm`, `rhythm-db`, `rhythm-bot`, десять deployment-файлов и `SHA256SUMS`.
- `dist/ritm-20261022-linux-amd64.tar.gz`: тот же каталог без исходников и секретов.
- `dist/ritm-20261022-ios-source.zip`: Xcode-проект, Swift core/tests, ресурсы и руководство. Это исходники приложения, не подписанный IPA.
- [Отчёт релиза](product-v1-release.md) содержит фактические проверки и оставшиеся внешние шаги.

Пересборка в новый каталог:

```sh
make qa-release QA_ARGS='--evidence-dir /tmp/rhythm-new-qa'
make release OUTPUT=/tmp/rhythm-new-linux-amd64
cd /tmp/rhythm-new-linux-amd64
shasum -a 256 -c SHA256SUMS
```

Команды не требуют Git и не создают коммитов. Не перезаписывайте прежний артефакт: собирайте в новый каталог. QA использует отдельные PostgreSQL 16/Chrome и не читает `.local/integrations.env`.

## Обновление VPS после восстановления SSH-доступа

1. Проверьте ключ сервера по ранее сохранённому `known_hosts`, свободное место, статус `rhythm.service`, PostgreSQL, Nginx и продление TLS. Запишите текущую цель `/opt/rhythm/current` для отката.
2. Запустите штатный `rhythm-backup.service`, проверьте его успешное завершение и наличие нового SQL-дампа. Копия на том же VPS не защищает от потери диска: отдельное хранилище пока не настроено.
3. Передайте **только Linux-архив** через доверенный SSH-канал, распакуйте в новый каталог `/opt/rhythm/releases/<release-id>` и выполните там `sha256sum -c SHA256SUMS`. Не загружайте `.local`, локальную БД, demo-аккаунты или iOS build cache.
4. Сверьте существующие units и конфигурации с файлами `deploy/`; не заменяйте вслепую Nginx или `/etc/rhythm/app.env`. Текущий релиз не добавляет миграции SQL, но установленный бинарник мигратора должен подтвердить применённую схему. При несовпадении остановитесь до переключения рабочего приложения.
5. Переключите `/opt/rhythm/current` на новый каталог через временную ссылку и атомарный `mv -T` в пределах `/opt/rhythm`. Перезапустите `rhythm.service`. Если штатный unit миграции использует `current`, выполните его до запуска приложения; при ошибке верните прежнюю ссылку и не продолжайте.
6. Проверьте HTTPS `/api/health` (`storage=postgresql`), страницу, вход синтетического проверочного аккаунта, запись/экспорт, удаление этого аккаунта и сохранность обычных данных. Не выполняйте destructive smoke на реальном дневнике.
7. При отказе верните предыдущую ссылку и перезапустите приложение. Откат бинарника не означает восстановление БД. Не восстанавливайте SQL-дамп поверх новых пользовательских данных без отдельного решения оператора.

## Telegram

Публичное меню, описание и три команды `@gymbro_ai` настроены через Bot API. Это не означает, что новый polling runtime уже установлен или новый токен передан работающему web-сервису.

Администратор должен добавить `TELEGRAM_BOT_TOKEN` в приватный `/etc/rhythm/app.env`, сохранив остальные настройки, `root:root`, `0600`; `PUBLIC_URL` у web и бота должен совпадать. Не передавайте секрет через argv, историю команд, репозиторий или архив релиза. Локальная приватная конфигурация уже содержит предоставленный владельцем токен; её содержимое не входит в артефакты.

После установки `rhythm-bot` установите unit `deploy/rhythm-bot.service`, выполните `systemctl daemon-reload` и включите его отдельно. До этого проверьте, что webhook отсутствует и другого polling consumer нет. Runtime намеренно отказывается удалять чужой webhook. Наблюдайте статус unit и журналы без токенов/тел пользовательских сообщений.

Владелец бота проверяет `/start` → «Мой ритм» → Mini App → создание записи → повторное открытие в настоящих Telegram iPhone/Android/Web. Main Mini App в BotFather настраивается отдельно. [Полные команды и ограничения](telegram-product.md).

## iPhone и публичные контакты

Откройте `mobile/ios/Rhythm.xcodeproj` в полном Xcode, выберите свой Team и окончательный bundle identifier. Затем выполните simulator/device build, проверьте физический iPhone, экспорт, вход, удаление аккаунта и повторный вход. Только после этого создавайте Archive/TestFlight. [Точная инструкция и privacy labels](ios-release.md).

Публичный email поддержки и сведения владельца будут добавлены позже по решению пользователя. До этого `/privacy.html` и `/support.html` прямо помечены подготовительными; их нельзя выдавать за завершённые условия публичного выпуска. Apple Developer, signing и отправка в App Store не выполнены.
