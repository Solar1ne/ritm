# Запуск Telegram Mini App

Код интеграции реализован. Подтверждение подписи проверяется локальными тестами. Живой запуск требует вашего бота, токена и публичного HTTPS-домена — они в текущей задаче не предоставлены.

1. Создайте бота через официальный [@BotFather](https://t.me/BotFather), если его ещё нет. Сохраните токен в секретах окружения сервера как `TELEGRAM_BOT_TOKEN`. Не вставляйте его во frontend, Git, URL сайта или скриншоты.
2. Разместите сервер по HTTPS. Задайте `PUBLIC_URL=https://ваш-домен` (без `/mini`), `ADDR=:8080` в контейнере и `DATABASE_URL` к постоянному PostgreSQL. Примените миграции; приватный session secret хранится в БД и должен входить в резервную копию. См. [PostgreSQL](postgresql.md).
3. В BotFather настройте Main Mini App либо Menu Button. URL приложения: `https://ваш-домен/mini`. Название кнопки: «Мой ритм». Эти способы запуска поддерживаются [официальной документацией Telegram](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button).
4. Откройте Mini App из Telegram. Пройдите настройку, отметьте самочувствие, закройте и откройте приложение — сервер должен вернуть тот же Telegram-профиль. Для Main Mini App доступна ссылка `https://t.me/имя_бота?startapp` после настройки.
5. Проверьте Android, iOS и Telegram Web отдельно: small screens, safe areas, dark theme, BackButton, сохранение и перезапуск. Браузерный `/mini` без initData — только предпросмотр, он не считается Telegram-авторизацией.

## Что делает интеграция

`frontend/static/telegram.js` подключает официальный SDK только для Mini App. Сервер получает raw `initData` через `POST /api/auth/telegram`, проверяет HMAC-SHA256 в constant time, возраст не более1часа и будущее не более30секунд, валидирует user ID. `initDataUnsafe` не используется как источник доверенной личности. Алгоритм соответствует [правилам проверки Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

Подтверждённая личность преобразуется в непрозрачный стабильный principal. Telegram-данные не сливаются с гостевым профилем автоматически. Для явного переноса можно заранее экспортировать гостевой JSON версии 2 и восстановить его в пустом подтверждённом Telegram-аккаунте. Переносятся профиль, сохранённые недели, факты, тренировки и настройки; исходная идентичность и cookie не переносятся. Непустой аккаунт restore не заменяет. Неуспешный Telegram-вход оставляет интерфейс заблокированным; повтор заново проверяет подпись, а не открывает старую cookie-сессию.

Браузер удерживает `sessionBinding` только для текущего состояния и отправляет `X-Rhythm-Session`. Сервер проверяет его для всех приватных операций, включая историю недель, импорт, restore, ассистента, календарь и экспорт, чтобы вкладка прежнего аккаунта не прочитала или изменила данные нового при общей cookie. Bootstrap `/api/state` допускается без binding; если заголовок передан, он проверяется. Черновик связан с этим же аккаунтом и восстанавливается только после успешной проверки личности.

На HTTPS Telegram-cookie использует `HttpOnly; Secure; SameSite=None; Partitioned`; перед выдачей удаляются прежние cookies обеих разновидностей. Это поддерживает Telegram Web iframe. Website-cookie используют SameSite=Lax. Новая подтверждённая Telegram-сессия содержит случайный токен и подпись server secret; на сервере хранится только хеш токена. Срок 30 дней от выдачи, GET его не продлевает. Выход отзывает токен; новый запуск из Telegram вновь проверяет initData. Старые подписанные сессии до расширения аккаунтами поддерживаются до истечения/отзыва. Политику сторонних cookie конкретных клиентов нужно проверить на живом размещении; CSP разрешает Telegram embedding. Секреты, initData и дневник не логируются. Вход по логину сайта и Telegram не объединяют личности автоматически. [Контракт сессий](adr/007-persistent-website-accounts.md).

## Docker + Caddy

Скопируйте `.env.example` в `.env` на вашем сервере, задайте реальный домен и токен. DNS A/AAAA должен указывать на сервер, порты80/443 — быть доступны. Затем:

```sh
docker compose up -d --build
docker compose logs --tail=50 app
```

Caddy получает TLS-сертификат и проксирует запросы к Go. Volume `rhythm-postgres` содержит текущую БД, аккаунты и ключ подписи. Для согласованного резервирования используйте `pg_dump` через [инструкцию PostgreSQL](postgresql.md); сохраняйте credentials окружения отдельно. `rhythm-data` предназначен только для legacy файлового режима. Секреты в env не публикуются клиенту. Конфигурация рассчитана на один процесс приложения и постоянный диск. Деплой не проверялся без домена и credentials.

## Проверка при подключении

- `GET /api/health`: `telegramConfigured:true`, storage доступно.
- Валидный вход создаёт/открывает Telegram-аккаунт; испорченная или просроченная подпись даёт401.
- При профиле 3 × 45 минут факт сна 5 / усталости 9 создаёт предложение 2 × 36 = 72 минуты; повтор с тем же ID не дублирует историю.
- Принятие предложения сохраняет его отдельно. Новая запись или изменение профиля не переписывает принятое расписание; до понедельника его можно отменить. В понедельник оно становится текущим, прежняя неделя остаётся в истории.
- Текущая дата и начало недели совпадают с `today/timeZone/currentWeekStart` API; исправление прошлой отметки проверяется по её сохранённому расписанию и окну 90 дней.
- Ошибка сохранения оставляет черновик, а не сообщение об успехе.
- Другой аккаунт не видит дневник первого; смена аккаунта в другой вкладке отклоняет запросы со старым binding, включая экспорт и календарь.
- Экспорт версии 2 восстанавливается в пустой аккаунт без переноса исходной сессии. Неполная или повреждённая копия ничего не сохраняет.

Настройки напоминаний и ICS с календарным уведомлением реализованы. Напоминание в интерфейсе зависит от открытого приложения; уведомления после его закрытия доступны через импорт ICS в календарь, если клиент календаря их поддерживает и пользователь разрешил уведомления. Серверные сообщения Telegram, webhooks и рассылки не реализованы. Для открытия Mini App polling-бот не нужен.
