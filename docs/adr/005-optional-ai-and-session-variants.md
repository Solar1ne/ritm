# ADR-05: необязательный AI и явные варианты занятий

Статус: принято, 17.10.2026. Дополняет ADR-02, не заменяя проверяемое ядро нагрузки.

Дополнение 17.10.2026: добавлен независимый адаптер DeepSeek Chat Completions, общий строгий контракт и выбор провайдера; согласие связано также с провайдером/моделью. Таймаут теперь настраивается в пределах1–30с (DeepSeek20с, OpenAI3с). [Реализация и evidence](../deepseek.md). Ниже сохранено исходное решение.

## Проблема и решение

Пользователь хочет понимать свой план в свободном диалоге, быстрее вводить дневник и подстраивать занятия под обстоятельства. Одни шаблонные ответы не покрывают US10. При этом презентация требует работы без LLM, объяснимости и согласия на передачу сведений о здоровье.

Добавлен узкий порт `AIGenerator` в HTTP-потребителе. `internal/aicoach` описывает независимый контракт и валидирует результат; `internal/openai` реализует один запрос Responses API через стандартную библиотеку. Ручной composition root подключает адаптер только при серверном ключе. Модель конфигурируема; исходная `gpt-4.1-mini` поддерживает структурированный ответ. SDK и сторонних Go-зависимостей нет.

Три задачи: вопрос по фактам, разбор последних 14 дней, черновик записи из фразы. В запросе нет имени и идентификатора аккаунта; для черновика не нужна история сна. Согласие связано HMAC с аккаунтом, задачей, точным контекстом, revision и сроком 5 минут. Пользователь видит контекст до отправки. Внешний вызов выполняется вне блокировки хранилища.

Строгая схема не доказывает истинность свободного текста. Проверяются размеры, обязательные поля, допустимые ссылки и инварианты черновика. Модель не получает tools, не выбирает нагрузку, не пишет в хранилище. Пользователь редактирует и подтверждает черновик через обычный API дневника. История AI в приложении не сохраняется. `store:false` не является обещанием Zero Data Retention у провайдера.

## Отказ, стоимость и восстановление

Вызов ограничен тремя секундами; автоматических повторов нет. На один процесс — не более четырёх параллельных вызовов, по умолчанию 60 попыток в час; на аккаунт — шесть за десять минут. Лимиты включают неуспешные попытки, поскольку нельзя гарантировать отсутствие тарификации на стороне провайдера. Карта пользователей ограничена 4096 элементами и очищается при запросе. Фоновые worker не нужны.

После трёх последовательных ошибок circuit открывается на 60 секунд. Затем допускается один пробный пользовательский запрос за раз; пять успешных проверяемых ответов закрывают circuit. Проверки — новые явно согласованные запросы пользователей, без фонового платного polling. Отмена клиентом освобождает слот и не считается сбоем провайдера. Старые конкурентные ответы не меняют новое поколение circuit. Запись дневника, правила и календарь продолжают работать во всех состояниях.

## Варианты занятий

Версионированный каталог определяет тип, текст и допустимые условия. Исходный снимок недели не меняется: отдельный `SessionAdjustment` хранит выбранный вариант, время, место и дату изменения. Наложение используется планом, историей, помощниками и ICS. Допускаются только известные сегодняшние/будущие занятия без отметки, в текущем или принятом следующем плане. Минуты не превышают исходные, учитываются ограничения восстановления. Замена на другой вид сама по себе не доказывает физиологическую эквивалентность.

Preview не пишет, apply/revert используют revision. Повтор уже выбранного варианта идемпотентен. Отмена будущей недели удаляет её варианты; восстановление копии валидирует весь граф. Укороченная/заменённая неделя не служит основанием для автоматического повышения объёма на 5%.

## Верификация и границы

Синтетические provider HTTP fixtures проверяют контракт API, отказ, таймаут, отмену, malformed/refusal/incomplete, запрет redirect и ограничения результата. HTTP-тесты проверяют согласие, утечки контекста, квоты, circuit, конкурентную запись, день/неделю и отсутствие автоматического сохранения. Браузерные fixtures проверяют UI; они явно не являются ответами живой модели.

Живой smoke требует ключ владельца и отдельный искусственный запрос. Сравнительный UX-тест остаётся способом проверить преимущество над универсальным чатом. Питание, HRV и состав тела реализованы отдельно в [ADR-06](006-measurements-and-nutrition.md); их наличие не выводится из появления AI. Прямые API часов и серверная доставка уведомлений остаются внешними интеграциями.
