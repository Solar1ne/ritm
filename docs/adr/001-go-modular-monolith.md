# ADR-01: Go-монолит и единый web-клиент

Дата: 17.10.2026. Статус: принято для текущего PoC. Связанные риски: T2, B1. Требования: NFR-02/03; истории US01–06, US11/12.

## Контекст

Презентация описывала будущий FastAPI + React + PostgreSQL, но исходного приложения в репозитории нет. Пользователь задаёт стандарт production-quality Go и просит сначала сайт, затем Telegram Mini App. Нужен работающий сквозной сценарий, который можно запустить и измерить локально, а правила ещё предстоит менять после экспертизы и UX-теста.

## Решение

Один Go-модуль `rhythm`, один серверный процесс, стандартная библиотека. Домен планирования — `internal/rhythm`; HTTP, Telegram auth и хранение — внешние к нему адаптеры. `cmd/server` вручную собирает зависимости. Статические HTML/CSS/JS modules встроены в бинарник. Клиент исполняется и в браузере, и в Telegram WebView и вызывает один API.

## Сравнение альтернатив

| Вариант | Соответствие задаче | Цена / риск |
|---|---|---|
| **Go modular monolith + browser modules** | Соответствует текущему стандарту команды; общий тестируемый domain; один процесс и артефакт запуска | Разметку, доступность и состояние UI нужно аккуратно поддерживать без framework; нет причины обещать лучшую производительность без замера |
| FastAPI + React из презентации | Работоспособный вариант; подходит команде, специализирующейся на Python/React | Новый runtime и dependency surface; мигрировать нечего, существующих преимуществ от кода пока нет |
| Микросервисы | Могут помочь при независимых владельцах и разных потребностях масштабирования | Сейчас добавляют сетевые сбои, deploy/trace complexity и распределённую согласованность без доказанной необходимости |
| Только браузерный алгоритм | Быстрый локальный макет | Не проверяет серверное сохранение, доступ, конкуренцию и реальный HTTP-путь |

Выбор Go не доказывает, что FastAPI медленный или непригодный. Он сокращает число различных runtime в этой команде и позволяет проверить правила, HTTP и конкурентность одним набором Go-инструментов. Выбор browser modules не запрещает framework позднее, если сложность клиента это оправдает.

## Последствия и границы

Домен не импортирует HTTP, Telegram SDK, SQL или файловую систему. Изменение adapter не меняет правила. Нет DI-framework, изменяемого registry в `init` и отдельного rule-engine сервиса. Один процесс означает единый отказ сервера; высокая доступность на текущем этапе не заявляется.

В презентации необходимо заменить название backend на Go и отделить текущий JSON adapter от целевого PostgreSQL. Иначе диаграмма описывает другой программный образец и не может служить evidence его критического пути.

## Проверка и пересмотр

Проверки: `go test ./...`, `go vet ./...`, `go test -race ./...`; `staticcheck ./...` при наличии; `go run ./cmd/rat`; HTTP load и браузерный проход. Зависимости подтверждаются review imports, а latency — измерением, не выбором языка.

Решение пересматривается при появлении независимых команд/нагрузок/SLA или когда UI становится трудно сопровождать. Само увеличение числа исходных файлов не является причиной вводить микросервисы.
