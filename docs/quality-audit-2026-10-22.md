# Проверка функций и исправления «Ритма» · 22.10.2026

Проверена локальная Go/JavaScript-сборка: автоматические тесты, реальные HTTP/SQL операции и пользовательские сценарии Chrome. Исправлены пять воспроизводимых ошибок. [Руководство по всем возможностям](features.md), [машинный итог](evidence/audit-2026-10-22/checks.json).

Использованы отдельный временный PostgreSQL 16 на `127.0.0.1:55439`, базы `rhythm_audit_test`, `rhythm_browser_test`, `rhythm_restore_test`, сервер `127.0.0.1:18081` и искусственные аккаунты. Пользовательские данные и публичный VPS в этом прогоне не участвовали. Результат относится к локальным исходникам; публикация исправлений на VPS требует отдельного развёртывания.

## Что исправлено

| Ошибка | До | После | Защита от повторения |
|---|---|---|---|
| F1: восстановление повышало минуты после изменения текущего плана/профиля | Текущие 3×15 → 72 минуты; текущие 1×15 при новом профиле 5×90 → 288 минут | Соответственно 30 и 15 минут; профиль и известная текущая неделя ограничивают предложение вместе | `internal/rhythm/recovery_test.go`: варианты, разные профили, округление, минимум, неизвестные минуты; HTTP: принятие → JSON-экспорт → восстановление → понедельник |
| F2: части интерфейса использовали часы устройства | При устройстве на день впереди менялись «Сегодня», окно прогресса и допустимая дата записи | Обзор, календарь, заголовок, дневник и прогресс используют `state.today` | `web/tests/server-date.test.js`, Chrome-регрессия `scripts/server-day-check.mjs` |
| F3: локальный помощник сохранял вчерашний ответ | `revision` не изменилась при смене дня — старый ответ оставался | Проверяется и версия дневника, и серверный день, включая незавершённый запрос | Две регрессии в `web/tests/features.test.js` |
| F4: импорт подтверждался для другой версии дневника | После обновления состояния форма отправляла новую `revision` со старым предпросмотром | Подтверждение связано с версией предпросмотра и аккаунтом; изменение требует нового просмотра | Регрессия устаревшего предпросмотра |
| F5: смена аккаунта во время чтения файла | Отложенный `file.text()` мог завершиться после сброса состояния и начать отправку старого файла | До сетевого запроса проверяются поколение операции, binding аккаунта и актуальность формы | Регрессия: после сброса старый файл вызывает 0 запросов |

Для восстановления обновлена проверка канонических принятых расписаний в `backup.go`: новые сокращённые планы проходят экспорт/restore; типы, названия, даты, одинаковая длительность и суммы продолжают проверяться. Существующие snapshots не переписываются. Формула и причины: [ADR-02](adr/002-deterministic-adaptation.md).

Один существующий domain-тест изменён с 36 до 33 минут, один browser-тест — с 96 до 72 минут: это следствия нового ограничения текущей неделей. Тесты по-прежнему проверяют повторяемость выбора, принятие конкретного предложения и сохранность снимков. Старые ошибочные ожидания не возвращались в production-код.

Дополнительно добавлены шесть тестов аккаунтов/адаптеров: устаревший вход при конкурентной смене пароля, отмена сохранения ledger в file/SQL, владение изменяемыми картами, ограниченный SQL lookup, перенос Telegram-сессии и отозванной гостевой cookie. Production-дефектов в этом участке не воспроизведено. Синтаксический `npm run check` теперь включает также `format.js` и `icons.js`.

## Решения и существенные риски

Минимальный production-diff меняет ветку recovery, проверку допустимого принятого плана и четыре frontend-модуля. Новые зависимости, transport DTO и публичные endpoints не потребовались.

| Аспект | Решение / проверка |
|---|---|
| Границы зависимостей, интерфейсы и composition root | Домен остаётся чистым расчётом; UI использует существующие поля. Новые порты/DI — N/A: внешняя граница не добавлялась |
| Context и I/O | Для изменённого Go-расчёта — N/A: локальные ограниченные вычисления. Для storage проверены уже существующие context/rollback |
| Lifecycle/конкурентность | Новые production goroutine — N/A. Проверены password/login race, rollback и клиентские операции после смены identity; fixture-сервер закрывается владельцем |
| Транзакции/атомарность | Границы сохранения прежние; SQL/file cancellation и полный restore проверены. Частичных пользовательских сохранений не обнаружено |
| Идемпотентность | Повтор отметки/импорта и потеря ответа проверены; предпросмотр импорта теперь связан с просмотренной revision |
| Совместимость | Старые v2 архивы остаются допустимыми. Новые уменьшенные принятые планы требуют обновлённого валидатора; старая сборка может отклонить их при restore. Уже принятые планы не пересчитываются автоматически |
| Ошибки и observability | Ошибка устаревшего предпросмотра объясняет необходимость повторной проверки. Recovery явно объясняет минимум и неизвестные минуты; секреты в evidence не записаны |
| Безопасность | Сохранены canonical validation, binding/CSRF и разделение аккаунтов; старый файл не отправляется с новым аккаунтом |
| Производительность/память | Расчёт ограничен размером недельного плана; новых фоновых работ/неограниченных коллекций нет. RAT и HTTP smoke повторены |

Остаточные ограничения: живой AI, настоящий Telegram, доставка фоновых уведомлений, внешние условия VPS и эффективность рекомендаций требуют отдельных проверок. Этот аудит не заменяет пользовательский пилот и экспертную оценку правил.

## Как повторить

Нужны Go 1.25+, Node, PostgreSQL 16, Chrome и уже установленный Playwright. `RHYTHM_TEST_DATABASE_URL` должен указывать только на отдельную тестовую БД с именем, заканчивающимся `_test`; тесты создают собственные схемы. Не задавайте здесь пользовательскую/production БД. [Подготовка PostgreSQL](postgresql.md).

```sh
go test ./...
RHYTHM_TEST_DATABASE_URL='postgres://TEST_USER@127.0.0.1:TEST_PORT/rhythm_test?sslmode=disable' go test -race -count=1 ./...
go vet ./...
staticcheck ./...  # если установлен
gofmt -l cmd internal web
npm test
npm run check
python3 scripts/test_dev.py
go run ./cmd/rat -json
```

Без test DSN PostgreSQL integration-тесты пропускаются: зелёный такой прогон не доказывает работу SQL. При ограничениях файловой системы задайте отдельные writable `GOCACHE`, `GOMODCACHE` и `STATICCHECK_CACHE`. В этом запуске использованы `/tmp/rhythm-go-cache`, `/tmp/ritm-audit-modcache`, `/tmp/rhythm-staticcheck-cache`; зависимости скопированы из существующего локального Go-cache без изменения `go.mod`/`go.sum`.

Для Chrome подготовьте отдельный сервер `127.0.0.1:18081` с мигрированной временной БД, без AI-ключей/Telegram token. Он должен быть собран после изменения исходников: frontend встроен в Go-бинарник. Наборы accounts/first-run проверяют именно порт 18081.

```sh
export PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright
export RHYTHM_URL=http://127.0.0.1:18081
RHYTHM_EVIDENCE_DIR=/tmp/ritm-browser-base node scripts/browser-check.mjs
RHYTHM_EVIDENCE_DIR=/tmp/ritm-browser-cycle node scripts/full-product-check.mjs
RHYTHM_EVIDENCE_DIR=/tmp/ritm-browser-ai node scripts/ai-product-check.mjs
RHYTHM_EVIDENCE_DIR=/tmp/ritm-browser-wellness node scripts/wellness-nutrition-check.mjs
RHYTHM_EVIDENCE_DIR=/tmp/ritm-browser-accounts node scripts/accounts-check.mjs
RHYTHM_EVIDENCE_DIR=/tmp/ritm-browser-first node scripts/first-run-check.mjs
node scripts/server-day-check.mjs  # собственный read-only fixture на 18085
go run ./cmd/loadtest -url http://127.0.0.1:18081 -rps 10 -duration 30s -output /tmp/ritm-load.json
```

После проверки остановите временные процессы и PostgreSQL. В этом рабочем каталоге нет `.git`; изменённые файлы проверены сравнением с отдельной исходной копией. Git-коммиты не создавались.
