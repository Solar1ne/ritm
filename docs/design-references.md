# Ритм: интерфейс на основе существующих продуктов

Этот документ фиксирует этап исследования и обновления интерфейса. Последующее расширение backend и полного набора функций описано в [текущем отчёте](full-product-release.md); нижеприведённые заявления о неизменности Go относятся только к исходному этапу дизайна.

Дата исследования: 17.10.2026. Источники — официальные сайты и справочные материалы. Открытые экраны Gentler Streak и Streaks просмотрены в браузере; функциональная модель Fitbod сверена с его Help Center. Закрытые приложения, платные функции и исследования их пользователей не проверялись.

## Что изменилось для пользователя

1. **Сегодня.** После создания профиля вместо общего вступительного текста появляется конкретное занятие или день отдыха. Выполненное занятие меняет карточку на «На сегодня — готово». Отметку можно исправить. Кольцо считает только факты текущего плана, без выдуманной серии и без обязательства тренироваться в дни отдыха.
2. **Самочувствие.** В форме можно выбрать 6/7/8/9 часов сна и один из четырёх уровней усталости. Точное число остаётся доступным в обычном поле. Выбор заполняет форму; запись происходит только после нажатия «Сохранить отметку».
3. **Прогресс.** Период 7/30 дней меняет реальные графики сна и усталости. Каждый день можно открыть для просмотра подробностей. Управление работает мышью, касанием и клавиатурой. На узком экране месячный график прокручивается внутри панели.
4. **Пустые состояния.** Пока профиля нет, недельный план явно обозначен примером. Графики не заполняются демонстрационными показателями. Отсутствие отметки не означает ноль часов сна.

## Контракт расчёта истории

- Период заканчивается сегодняшним днём по Москве; начало включительно: сегодня минус 6 или 29 дней.
- Для каждого дня берётся последний известный сон и отдельно последняя известная усталость в порядке сохранения. Запись только усталости не стирает сон.
- Несколько записей за день дают один день в среднем. Сон `0` — настоящий измеренный ввод, `null`/отсутствие поля — неизвестно.
- Выполненные занятия считаются по уникальным `sessionId`; исправление `done → missed` уменьшает число выполненных.
- Минуты показываются только для текущего плана. Длительность прошлых занятий не восстанавливается из сегодняшних настроек, поскольку исторические снимки расписаний ещё не хранятся.
- Переключение периода и просмотр дня не вызывают запись на сервер. Агрегация не меняет входные массивы.

Go-ядро, API, storage, авторизация, схема данных и пороги адаптации не менялись. Новых зависимостей нет. Изменения транзакций, composition root и lifecycle: N/A — меняется только представление уже сохранённых фактов и управление формой. Риски этого diff: неверная агрегация, подмена неизвестного значения нулём, потеря фокуса, переполнение мобильного экрана и регрессия повторного сохранения.

## Использование на защите

Показать последовательность: создать план → отметить занятие → увидеть кольцо и статус → выбрать сон/усталость → открыть 7/30 дней → объяснить предложение следующей недели. Сравнение с существующими продуктами объясняет выбор интерфейса. Преимущество Ритма и удержание пользователей всё ещё требуют UX-теста и пилота, описанных в [плане](implementation-plan.md).
