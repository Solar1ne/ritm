# Ритм v1: план выпуска web, Telegram и iPhone

Дата: 22.10.2026. Владелец интеграции — root. Работа организована через ECC `product-capability`, `team-agent-orchestration`, `production-audit`, TDD и независимую приёмку. Пользователь запросил оба семейства моделей: GPT-6.1 Sol и GPT-6 Astra. Одновременно доступны root и три агента; задачи выполняются волнами.

## Согласованная граница

Пользователь выбрал все три поверхности. Web и Telegram должны использовать существующий Go/PostgreSQL-продукт. Для iPhone пользователь подтвердил отсутствие оплаченного Apple Developer и запросил подготовку приложения к регистрации/публикации. Поэтому готовность исходников iPhone, проверка переносимого core, сборка iOS SDK, подпись и публикация — отдельные проверяемые этапы. На этой машине пока установлены только Command Line Tools, без Xcode/iOS SDK.

Основной продуктовый цикл уже существует: профиль → сохранённый план → дневник → предложение → явное принятие → история. Также уже реализованы аккаунты, резервные коды, измерения, питание, импорт, AI с согласием, календарь активности и итог недели. Эти возможности проходят регрессионную проверку и не создаются повторно.

| Поверхность | Критерии |

## Ограничения и риски Go

- Новые данные `limits` — добавочная HTTP-проекция доменных констант, не новый слой хранения. Восстановление игнорирует производные лимиты из чужой выгрузки.
- Telegram — отдельная внешняя граница со stdlib HTTP, context первым аргументом, таймаутами, ограниченным чтением, редактированными ошибками и владельцем остановки. Бизнес-ядро не зависит от Bot API.
- Существующие транзакции, row locks, revision/binding и snapshots сохраняются. Миграции не нужны для web-улучшений. Ошибки сохранения не выдаются за успех.
- Неприменимые новые DI/брокер/registry — N/A: приложение остаётся модульным монолитом. Для web-представлений новые goroutine/транзакции — N/A.
- iPhone API-клиент соблюдает существующую авторизацию и ревизии; секрет бота никогда не относится к приложению.
- Service Worker кэширует только явный список публичных файлов, не API, дневники, экспорт или credentialed JSON. Установка на телефон не означает автономное сохранение.
- Заполнение недель при rollover требует отдельной проверки: экспорт не должен становиться недоступным из-за попытки материализовать новую неделю сверх лимита.

## Проверки и выпуск

1. Целевые RED→GREEN тесты каждого изменения и ревью diff.
2. `go test -race -count=1 ./...` на изолированной SQL БД, `go vet`, `staticcheck` при наличии, gofmt.
3. Frontend/Python/Swift core тесты; синтаксис всех production JS-модулей.
4. Все существующие browser suites плюс новая приёмка web-v1. Отдельная проверка отсутствия приватного кэша.
5. Linux bundle, manifest и SHA256SUMS; проверка чтения public configuration, таймаутов и cleanup.
6. Проверка реального Bot API/configuration, HTTPS health и пути `/mini`; настраиваемые runtime/деплой после подготовки reviewable artifact.
7. Собрать финальный отчёт: что готово, какие внешние шаги нужны владельцу, точные команды установки/восстановления.

Внешние шаги имеют конкретных владельцев: Apple Developer/Xcode/signing — владелец аккаунта; BotFather Main Mini App и реальная проверка iOS/Android/Web — владелец бота с готовой конфигурацией; off-host backup/уведомления об аварии — оператор, которому нужны destination и доступ. Недоступные внешние проверки не заменяются fixtures.

## Уточнения после ревью

Добавлено отдельное удаление аккаунта Ритма для подготовки App Store: password + явное согласие + просмотренная revision, PostgreSQL-транзакция и отзыв всех сеансов. Существующее очищение дневника сохраняет прежний контракт. Схема SQL и Go-зависимости не менялись; файловый adapter честно отклоняет недоступную атомарную операцию.

Независимое ревью выявило и закрыло гонку старого guest INSERT после регистрации/удаления; подтверждения iPhone теперь закреплены за снимком и identity. QA учитывает весь Go embed-каталог независимо от расширений и отказывается создавать bundle через dangling symlink. Детальные результаты — в отчёте релиза.

Владелец явно отложил SSH-доступ и email поддержки. Граница этого этапа: проверенные локальные артефакты и инструкция; публичный runtime не обновляется, App Store не отправляется.
